# TrustVault — Threat Model

This file documents every threat considered during development, the control applied, the test that verifies it, and the residual risk that remains. Honest entries score higher than clean ones.

---

## Threat table

| # | Threat | Mitigation | Test | Residual risk |
|---|--------|------------|------|---------------|
| T1 | **Insecure direct object reference (IDOR)** — attacker guesses or enumerates a document UUID and fetches it directly | `access()` helper re-checks per-document grants on **every** request; returns 404 (not 403) to prevent existence confirmation | `test_idor_direct_document_url`, `test_idor_direct_download_url` | UUIDs are not guessable but are not secret by design; a document owner could leak their own ID |
| T2 | **Download bypasses UI control** — blob fetched directly from storage path | Local blob directory is outside all static-file routes; Supabase Storage uses server-side requests and returns bytes only after `access()` succeeds; no public or signed URLs are issued | `test_static_route_does_not_serve_blobs`, mocked `test_supabase_blob_storage_round_trips_private_object`, `test_revoked_grant_does_not_fetch_blob` | The initializer checks bucket privacy, but the running app does not re-check it on startup. A bucket made public later or leaked server key could expose objects. No real Supabase provider integration was tested |
| T3 | **Revoked user reuses old link or session** | No bearer file URLs issued; grants are re-checked on every request; revocation deletes the `grants` row immediately; `current_user()` checks `enabled` flag | `test_revocation_is_immediate` | Copies already downloaded before revocation cannot be recalled; out-of-scope by design |
| T4 | **Read-only grantee tampers with metadata** | `access()` is called with `level='edit'` on the edit endpoint; read grant does not satisfy the edit check | `test_read_grant_cannot_edit_metadata` | None identified |
| T5 | **Non-owner revokes or deletes** | `owner_access()` checks `doc.owner_id == user.id`; raises 403/404 on failure | `test_viewer_cannot_revoke`, `test_viewer_cannot_delete`, `test_editor_cannot_delete` | None identified |
| T6 | **CSRF forces grants, deletions or uploads** | Per-session `secrets.token_urlsafe(32)` token validated with `hmac.compare_digest`; `same_site='strict'` cookie; CORS not open | `test_csrf_blocks_upload`, `test_csrf_blocks_grant`, `test_csrf_blocks_delete` | XSS on the same origin could steal the token; Content-Security-Policy `script-src 'self'` limits the attack surface |
| T7 | **Malicious executable disguised as document** | Extension allow-list (`ALLOWED`); magic-byte check per suffix; 8 MB cap; `text/plain` checked for null bytes | `test_pdf_magic_byte_required`, `test_png_magic_byte_required`, `test_txt_with_null_bytes_rejected`, `test_disallowed_extension_rejected` | **Accepted:** no antivirus scan or full-format parser; ZIP bombs not blocked; do not use with untrusted uploaders |
| T8 | **File path traversal** | Storage key is a random UUID generated server-side; client-supplied filename is only stored as `original_name`, never used for disk I/O | `test_path_traversal_attempt_rejected` | UUID collision is astronomically unlikely; no other path |
| T9 | **Unauthenticated access** | Every document endpoint checks `current_user()` first; returns 401 or redirect to login | `test_unauthenticated_view_redirects_or_errors`, `test_unauthenticated_access_is_audited` | Session cookie could be stolen if TLS is not enforced; `TRUSTVAULT_HTTPS=1` must be set in production |
| T10 | **Audit entries silently omitted for denied access** | Denials are committed in `access()` and `owner_access()` before raising HTTP exceptions. Success audit rows for mutations share the mutation transaction | `test_idor_denied_access_is_audited`, `test_unauthenticated_access_is_audited`, `test_document_edit_rolls_back_if_audit_cannot_be_written`, `test_upload_rolls_back_audit_failure_and_removes_blob` | A database outage prevents both a mutation and its corresponding success event; a denial may return a server error if its audit write fails. Use an external append-only sink in production |
| T11 | **Audit record edited or removed after incident** | HMAC-keyed hash chain: each event commits `prev_hash` and `event_hash`; `audit_integrity()` replays the chain | `test_audit_tampering_detected`, `test_audit_hash_field_tamper_detected`, `test_audit_chain_cannot_detect_tail_truncation_without_external_checkpoint` | **Accepted weakness:** deleting tail events is not detectable without an external checkpoint; an attacker with both the database and application secret can recompute valid hashes. Use a remote append-only sink with independently stored checkpoints |
| T12 | **Brute-force / credential stuffing on login** | In-memory sliding-window limiter: up to 10 attempts per direct peer address in 5 minutes; further attempts are blocked for 15 minutes. Argon2 raises per-guess cost. Untrusted `X-Forwarded-For` is ignored | `test_rate_limiter_blocks_excessive_attempts`, `test_forwarded_ip_header_is_not_trusted_for_login` | **Accepted:** limiter is in-memory and per-process; restart or multiple workers reset/distribute state. Production should use a shared limiter or edge control. Behind a proxy, direct peer may identify the proxy, so only trust forwarding metadata from explicitly allow-listed proxies |
| T13 | **Admin reads documents they do not own** | `authorized()` checks ownership or named grants only; `admin` role confers no implicit document access | `test_admin_cannot_read_owner_document`, `test_admin_cannot_grant_access_to_others_doc` | None; confirmed by test |
| T14 | **Disabled / fired user continues to access** | `current_user()` checks `user.enabled` on every request; admin can disable via `/admin/users/{id}/disable` | `test_disabled_user_login_rejected`, `test_disabled_user_active_session_denied` | Sessions are not explicitly invalidated from the server side (session store is the signed cookie). The `enabled` check on every request achieves the same effect without a server-side store |
| T15 | **Re-sharing by a grantee (confused deputy)** | Grant endpoint uses `owner_access()` — only the document owner may invoke it | `test_non_owner_cannot_grant` | None identified |
| T16 | **Admin management actions untracked** | `user_disable`, `user_enable`, `user_create`, `role_change` are all audited | `test_user_disable_audited` | None identified |
| T17 | **Dashboard leaks document IDs of unauthorized documents** | Dashboard filters with `authorized()` before adding to the result list; title search happens after the auth filter | `test_dashboard_hides_unauthorized_docs` | None identified |
| T18 | **Session fixation** | `request.session.clear()` is called before writing the new uid on successful login; new CSRF token issued | Manual review of `login()` in main.py | None identified |
| T19 | **Clickjacking** | Middleware sets `X-Frame-Options: DENY` and `frame-ancestors 'none'` in CSP | Source inspection; no dedicated header assertion or live header check recorded | Header behavior should be covered by a regression test and checked at the deployment edge |
| T20 | **Content-type sniffing** | Middleware sets `X-Content-Type-Options: nosniff` | Source inspection; no dedicated header assertion or live header check recorded | Header behavior should be covered by a regression test and checked at the deployment edge |
| T21 | **Open redirect** | All redirects use literal hardcoded paths; no user-supplied redirect parameter | Code review | None identified |
| T22 | **Mass assignment / parameter pollution** | FastAPI validates every request parameter by type; extra fields are ignored | Framework-level | None identified |
| T23 | **SQL injection** | SQLAlchemy ORM parameterizes user-supplied query values; fixed raw SQL is limited to database control statements such as the PostgreSQL advisory lock | Source inspection | No dedicated SQL-injection test identified; review any future raw SQL carefully |
| T24 | **Cache poisoning / stale page served to wrong user** | Middleware sets `Cache-Control: no-store` on responses | Source inspection; no dedicated header assertion or live header check recorded | Shared caching proxies upstream could ignore this; verify edge behavior and disable caching for authenticated pages |
| T25 | **Concurrent audit chain collision** | PostgreSQL appends acquire a transaction-scoped advisory lock before reading the prior hash; the lock is held through the enclosing mutation/audit commit | Mutation audit tests verify same-transaction behavior; live multi-worker PostgreSQL test not run | SQLite is intended for local/single-process use; multiple processes and PostgreSQL deployment have not been integration-tested. Keep an external audit sink/checkpoint for production |
| T26 | **Ephemeral storage loss** | Render serves the app; the application supports Neon PostgreSQL through `DATABASE_URL` and Supabase objects through `TRUSTVAULT_STORAGE_BACKEND=supabase`; local storage remains configurable for development | `render.yaml` and application configuration review; mocked storage test only. Public GET `/health` returned 200 on 2026-10-24 | The Render service responds, but this audit did not inspect hosted environment settings or verify Neon connectivity, real bucket privacy, write/read behavior, or persistence after restart. Review provider limits and retention; Render's local filesystem remains ephemeral |
| T27 | **Insider captures file content** | Downloads require an active, unexpired, enabled session with an active grant | Access policy | Authorised users can screenshot / copy a file they have legitimately downloaded; out-of-scope |
| T28 | **Weak session secret on first run** | Local development generates an ephemeral secret with a warning; HTTPS mode requires a configured secret and sets Secure session cookies | `test_https_mode_requires_a_stable_session_secret`, `test_https_mode_sets_secure_session_cookie` | Ephemeral local secret invalidates sessions on restart. Production must configure a stable, high-entropy secret and HTTPS |
| T29 | **Malformed document ID causes denied-request audit failure** | `access()` rejects identifiers longer than the 36-character database column limit before querying; it records the denial with a null `document_id` and fixed safe detail | `test_overlength_document_id_is_denied_and_audited_under_postgres_column_limit` simulates the PostgreSQL `varchar(36)` constraint while using isolated SQLite | This is a simulated constraint, not a PostgreSQL-server integration test |
| T30 | **Object deletion fails after database commit** | The delete handler removes the document and commits its audit event before asking the storage backend to delete the object | Source inspection only; no storage-delete failure test | If the storage request fails, the client can receive an error after the database deletion has committed, leaving an orphaned object. A retry/outbox process would be needed for reliable cleanup; it was not implemented |

## What we deliberately did not build

- **MFA / TOTP** — left out intentionally; a username+password system is the stated scope. Adding MFA would require an authenticator-app flow.
- **Password reset / email** — left out; no email transport configured. Admins reset passwords by creating new accounts.
- **File versioning** — not in scope for this submission; noted in README.
- **Antivirus scanning** — magic bytes + extension allow-list is the stated check. Full AV would require a sidecar service.
- **Live object-storage integration** — a Supabase Storage adapter and private-bucket preflight exist, but this audit did not verify a real bucket or provider credentials.
- **Share links with expiry** — deliberately omitted; bearer links are a known risk for document systems and the problem statement does not require them.
